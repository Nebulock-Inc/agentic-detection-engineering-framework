## Problem

Detection engineering has no memory and no lifecycle. Rules accumulate as YAML in upstream repositories, but every fact about *why* a rule exists, *what* telemetry shaped it, *how* it was iterated on, *who* gates its deployment, and *when* it should be tuned or retired lives in chat threads, ticket comments, and individual recall. Across teams the loss is structural: prior reasoning is unavailable to the agent or analyst encountering the rule next, AI augmentation has nothing durable to ground in, and tuning/deprecation decisions repeat.

Adjacently, the threat-hunting side of the same problem already has a solution — ATHF — but the threat-hunting and detection-engineering lifecycles need separate frameworks, not a single conflated one.

## Vision

ADEF is the detection-engineering sibling of ATHF: a small, opinionated, self-contained Python framework (`adef`) that turns every detection into a first-class, journalled artifact moving through a five-stage lifecycle (FORGE — Find → Observe → Refine → Govern → Evolve). A new analyst, an AI agent, or a future-you can open the journal and reconstruct the entire reasoning trail in seconds. Memory queries traverse YAML and journals together. New detections originate from a CTI URL or a hunt promotion in minutes, not days. ATHF and ADEF are paired siblings, both legible to humans and agents, neither subordinate to the other.

The euphoric surprise on encounter is: "this *is* the framework I would have wished into existence — minimal moving parts, total memory, and the agentic surface is just there."

## Out of Scope

- Replacing the upstream YAML rule schema. Rules stay where they are; ADEF wraps and journals.
- Introducing new engine types beyond `sigma`, `sql`, `sch_sql`, `composite`. The four engines are settled.
- Vendor-specific API connectors inside the framework (CrowdStrike, Splunk, SentinelOne, etc.). Connectors live elsewhere.
- Replacing ATHF. ADEF and ATHF are paired siblings.
- Web UI. CLI and MCP are the only user-facing surfaces in v0.1.0.
- Auto-deploying rules without human approval. ADEF can recommend; humans gate.
- Extracting a shared core library. Duplication between `adef` and `athf` is accepted in v0.1.0.
- Long-running orchestration daemons, agent-to-agent handoff, autonomous deprecation. v0.2+ surface.

## Principles

- **Wrap, don't rewrite.** Upstream rule-engineering agents stay intact; ADEF adds a thin lifecycle-aware orchestration layer. Upstream YAML is never modified by an ADEF code path.
- **Memory is markdown.** Journals are human-readable, AI-readable, version-controlled. The shape of the markdown IS the schema.
- **Lifecycle is a five-stage loop.** FORGE — Find, Observe, Refine, Govern, Evolve. Each stage is idempotent, each transition is timestamped, each step writes durably.
- **Plugin parity with ATHF.** Same Click + entry-point + FastMCP shape; same conventions for commands/agents/mcp_tools entry-point groups. A reader of ATHF's source recognizes ADEF's source immediately.
- **Anti-goals are anti-criteria.** Out-of-scope items are CI-enforced, not hopes.
- **ADEF is built standalone and open-source first; internal adopters come later, never the reverse.** ADEF must stand on its own as a public framework with zero dependency on — and zero design input from — Nebulock's internal repositories (detect-vault, hunt-vault, the Platform). Those are *future adopters* of ADEF, not sources for it. In practice: an internal repo is never a reference corpus, never a justification for an ADEF feature, and never the shape a public interface is fitted to. If a capability is only explicable by pointing at internal tooling, it does not belong in ADEF yet. Once ADEFv2 is finished, the integration runs the other direction — ADEF's concepts get worked *into* detect-vault and the Platform. This widens the 2026-06-16 vendor-neutralization decision, which covered only literal package names in source and left design inputs unguarded.

## Constraints

- Python 3.10+ only.
- Distribution name `agentic-detection-engineering-framework` (PyPI). Importable package `adef`. CLI `adef`. Repo at `~/work/agentic-detection-engineering-framework/` mirroring ATHF's full-name convention.
- Entry-point groups: `adef.commands`, `adef.agents`, `adef.mcp_tools`.
- Workspace lives at `~/work/adef-workspace/` (decided per goal Q1) — fresh top-level workspace.
- D-XXXX is a journal ID. Upstream rules continue to use UUIDs. Mapping is stored in journal frontmatter as `rule_uuid:`.
- No new engine types. No vendor API connectors. No web-UI dependencies (`flask|fastapi|starlette|django|next|react`).
- Hard invariant: no path under any rule `detections/` directory is opened or written by any `adef.*` import.

- 2026-07-22 — **Alias vocabulary gap: identified, mitigated in skills, deferred to v2.** A folded field keeps only the canonical spelling's harvested `values`; the alias spelling's value vocabulary is discarded. In the SIEM each spelling only matches its own vocabulary (`Status=0xc000006d` / `status=failure` both match; `Status=failure` silently matches nothing) — so aliases assert *same field, addressable by either name*, never *values interchangeable across names*. Consequences for agentic authoring: (1) an agent that authors with the alias spelling + schema values produces a legal-per-schema query that never fires and no gate catches it; (2) a team preferring the non-canonical namespace (CIM-first vs raw-first) has no home for that preference — canonical is chosen by event count, a statistical accident, not policy (live export: CIM won `user`/`status`/`signature`, raw won `Name`/`ProcessID`). Mitigations today: authoring rule added to the `detection-author` skill (values pair with the spelling they were harvested from; prefer canonical; teams authoring in the alias namespace split encoding-variant folds with `--no-fold`, which gives each spelling its own vocabulary as separate known fields — `check` still resolves both); hand-corrections carry `corrected` provenance and survive re-ingest. **v2 items:** per-alias values (each spelling keeps its vocabulary inside one folded entry — makes folds strictly better than splits) and a namespace-preference key (config or per-source `prefer: cim|raw`) so schema-grounded authoring steers by team convention, enabling an eventual value-aware `schema check` that catches the never-fires class.

- 2026-07-22 — **`adef sync` design locked (design-before-build; no code yet)** — `docs/plans/2026-07-22-adef-sync-design.md`. Addresses the biggest unaddressed trust risk (stale catalogs) and the concrete durability hole our enrichment now sits over (re-catalog assigns fresh IDs → orphans MITRE tags, authored drafts, journals). Design decisions:
  - **Governing principle: ADEF is never in the write path.** `sync` *observes* changes; it never mediates them. Catalog = disposable index (pure derivation, re-derive freely); journals = the only durable data. The one hard problem is **identity** — when a rule changes, which `D-XXXX` is it?
  - **Identity cascade** (first match wins): embedded UUID → content-hash unchanged → same-path-new-hash (modified) → fuzzy title/query (renamed, attach `needs_review`) → no match (new) → source gone (**orphaned, never deleted** — the "why" outlives the rule). **Enrichment fields (`mitre`/`status`/`stage`/`owner`/journal) are preserved across re-derivation; only derived fields update** — this is the fix for the wipe-on-recatalog hole.
  - **Persist three identity fields** the record lacks today: `rule_uuid` (already on `DiscoveredRule`, just not written — smallest/highest-value change, worth doing on its own), `source_hash` (SHA-256 of source bytes), `catalog_sha` (repo HEAD at catalog time, git only).
  - **Lean on git**: `catalog_sha` vs HEAD = one-shot staleness check; `git diff --name-status` gives adds/mods/deletes+renames (kills the fuzzy-match need for git repos). Hash-diffing is the fallback for non-git (SIEM exports). No config — detect the git work tree.
  - **Every read path is staleness-aware** (CLI banner, MCP `stale`/`commits_behind` annotation) — a confident AI answer from a stale catalog is the exact trust-killer this exists to prevent.
  - **Out-of-band edits become a feature**: modified rules auto-append a journal entry with the diff + harvested git commit message/PR ref — journals accumulate rationale even for teams who never manually journal.
  - **CI, not discipline**: `adef sync` on merge, or `--check` PR comments; same seam off a scheduled SIEM export. Command surface: `adef sync [--check] [--dry-run]`, reusing `discover_rules` + `Catalog` (sync = catalog + a `reconcile()` core, not a parallel walker). Open questions (catalog-becomes-sync?, fuzzy threshold, sha granularity, orphan surfacing) enumerated in the doc. Read-only invariant unchanged.

- 2026-07-22 — **`adef sync` reconciler built (sync step 3; the durability fix)**. Implements the design above. Decisions taken while building:
  - **Reconciler is pure logic, I/O in the command.** `adef/core/reconcile.py`: `reconcile(existing_records, discovered_rules, rule_root)` → a `list[PlanEntry]` (per rule: UNCHANGED / MODIFIED / NEW / ORPHANED). - 2026-07-22 — **Built-in extractors vs. profiles: grow profiles to scale to format *variants* (analysis; design-before-build)** — `docs/plans/2026-07-22-unify-on-profiles-design.md`. - 2026-09-18 — **ADEFv2 kickoff: Refine chain goes native by default (Shortcut epic 9324, stories 9331/9332/9333).** Since v0.1.0, `adef detection refine` only ever ran the Refine chain's three steps (RuleSimilarity, RuleOverlap, Verification) as thin `ADEF_WRAPPER_<KEY>` dispatchers to an upstream package — unconfigured (every real install), the step raised `WrapperUnavailable` and the chain logged "not configured." ADEFv2's first slice replaces that with real, vendor-decoupled implementations that just work out of the box, while keeping the wrapper env var as a fully-supported opt-in override (byte-for-byte the old behavior when set). Decisions:
  - **RuleSimilarity is agentic-by-nature, not vendor-free-by-default.** Epic owner direction (2026-09-18): the deterministic path is the guaranteed fallback, not the ceiling — `adef/agents/rule_similarity.py` always ranks the catalog with the existing BM25 engine (`adef.core.memory.MemoryIndex`, the same index `detection search` already builds), then optionally reranks just that shortlist with an LLM judge. `--similarity-mode {auto,bm25,llm}`; `auto` (the default) uses the LLM when `ANTHROPIC_API_KEY` is set and the new optional `llm` extra (`anthropic` SDK) is installed, else stays BM25-only — no LLM SDK is ever a required dependency. Retrieve-then-rerank keeps cost/latency bounded by `top_k`, never catalog size. **Native and vendor-free are not the same guarantee**: only `bm25` mode makes no network call; `auto`/`llm` can send the target's title/MITRE/query (truncated 500 chars) plus each shortlisted candidate's id/title/snippet to the Anthropic API — the snippet is built from both the journal body and the catalog search text (`record_search_text`: title/MITRE/platform/data_source/format/query), so catalog and query content can be disclosed too, not just journal prose.
  - **LLM judge response is fully schema-validated, not trust-and-coerce.** `json.loads` accepts literal `NaN`/`Infinity`, and a judge could omit a candidate, duplicate an ID, or return an unknown ID. Any of these — plus a non-finite/out-of-range confidence or non-string reasoning — now routes through the same `bm25_fallback` path already used for unparseable JSON, rather than silently mixing an LLM confidence score with a raw, unbounded BM25 score in one sorted list (found live via CodeRabbit review on the implementation PR, fixed before merge).
  - **RuleOverlap** (`adef/agents/rule_overlap.py`) is a deterministic, stdlib-only (`difflib`/`hashlib`) port of duplicate/complementary/redundant classification within one MITRE technique cluster — no LLM, ever, ported from detect-vault's `RuleOverlapAgent._analyze_cluster_deterministic` reference behavior. - 2026-09-21 — **Detection health capture: metrics, performance, and drift (Shortcut story 9342, spike).** Design agreed, **not yet implemented** — full detail in `internal-docs/plans/2026-09-21-vendor-capture-design.md`; story 9335 owns the build. Two questions: what does each measurable concretely mean, and how does ADEF capture it without violating `tests/test_no_vendor_connectors.py`. Decisions:
  - **Five versioned document kinds, one self-describing `adef ingest <file>`.** `metrics`, `performance`, `deployment_drift`, `field_observations`, `source_health` — bulk, keyed by `D-XXXX`, routed on the document's own `kind` rather than a CLI flag the producer could mismatch. ADEF never queries a deployment target; the producer (human, script, or an assistant session with its own tooling) hands over a file. Stored under `<workspace>/health/` as latest-snapshot plus append-only `.jsonl` history — the hybrid is what makes trend answerable without unbounded growth. `adef health` is the fleet report, a peer of `adef coverage`.
  - **Metrics are counts, not ratios** (`signal_count`, `true_positive_count`, `false_positive_count`, `unlabeled_count`, `last_true_positive_at`). A ratio cannot be re-aggregated across windows; counts derive ratios and the reverse fails. Matches FIRST.org's Detection Engineering Metrics Catalog, the nearest published standard. An absolute `last_true_positive_at` replaces a stored `days_since_true_positive`, which is wrong the moment it is written. `TuneRecommenderAgent` keeps its current dict shape behind a thin adapter.
  - **Drift is two failure modes, not one.** *Deployment drift* (deployed rule ≠ catalogued source) is ingested and compared **version-reference first** — a version integer, etag, or deploying commit is exact and needs no normalization — falling back to query text when the target exposes no such identifier. *Efficacy drift* (logic unchanged, ground moved) is **derived** from history + schema state + source health, with an optional `field_observations` ingest for the value-shape case ADEF cannot see. *Adversary/TTP drift* is named and explicitly **out of scope** — not derivable from telemetry. `sync`'s `source_hash` is unusable here: it digests raw file bytes, and a deployed rule is not a file.
  - **Every efficacy-drift finding must name its alternative explanation.** A volume cliff is correlated against `source_health` before it is ever attributed to the rule — practitioner reporting puts roughly half of detection failures down to log-collection gaps, so the naive version would confidently blame the rule for a dead feed about half the time it fires. Trend uses EWMA, not a static threshold (control-chart guidance for gradual drift); fewer than four ingests reports "insufficient history" rather than guessing.
  - **Normalization is a closed, ADEF-shipped set the document selects from** (`collapse_whitespace`, `strip_sql_comments`, `strip_trailing_semicolon`), never producer-supplied regex — that would be a ReDoS surface and an unauditable comparison contract, and it follows the extraction-profile precedent (dot-paths, not JSONPath, to keep the human gate reviewable). Every transform is lossy by definition, so the set admits only transforms that cannot change behavior; anything touching case, quoting, numeric form, or parens is deliberately excluded. **`_normalize_query()` is not reused** — it lowercases, so `user='Admin'` → `user='admin'` erases a real behavior change on a case-sensitive backend. It was built for fuzzy similarity, which is the opposite problem.
  - **`ADEF_WRAPPER_PERFORMANCE_METRICS` → `ADEF_WRAPPER_METRICS`**, outright, no shim (unreleased; a deprecation window protects nobody — same reasoning as the 2026-07-20 removals). It always returned the metrics measurable under a performance label. **No new wrapper bindings** — `ADEF_WRAPPER_PERFORMANCE`/`_DRIFT` were proposed by analogy and dropped: no user has asked, and an unused public env-var contract is far easier to add than to remove.
  - **The Evolve stage gains a chain symmetric with Refine's.** Found during design: `adef detection evolve` only advances the stage, while `TuneRecommenderAgent` and `DeprecationRecommenderAgent` sit implemented but unwired, reachable only via MCP. Evolve will read stored health and run both, appending `### Evolve / …` journal blocks with the same never-abort semantics as `refine_chain.py`.
  - **Standalone-first discipline applied mid-design** (see Principles): an earlier draft justified a `bind_params_to_qmark` transform from an internal pipeline's behavior and used an internal corpus as the reference measurement. Both were removed — the shipped transforms are justified from language semantics alone, and the internal measurement survives only as a clearly-labeled non-normative data point in the design doc.

- 2026-09-23 — **Similarity mode inverted: the caller ranks by default, not ADEF (Shortcut 10185 + the CLI default flip).** Plan: `docs/superpowers/plans/2026-09-23-similarity-mode-agent-inversion.md`. Until now `auto` was the default, so an `ANTHROPIC_API_KEY` in the environment meant ADEF made its own outbound call while an agent was already driving it — the user paid twice, the reasoning hid in a subprocess, and the calling agent (which holds context ADEF does not) could neither see nor challenge it. For a framework named *Agentic*, whose likely first encounter is a user opening the repo in an AI-enabled IDE, that is backwards. Decisions:
  - **New `agent` mode returns the shortlist and ranks nothing.** It hands back the target's **and** each candidate's **untruncated** `query` plus `mitre`/`platform`/`data_source` — the full text, not the `llm` path's 500-char cut — because a snippet is not enough to judge *logic* similarity. Both sides matter: shipping only the candidates' queries (the first cut, caught by CodeRabbit) left the caller with nothing to compare them against short of another round trip, which is precisely the cost the inversion exists to remove. That payload difference is what makes the mode more than a `bm25` rename. It makes no network call, guaranteed by construction: the branch returns before `_llm_available()` or an injected client is ever consulted.
  - **Defaults are set by entry point, never by environment detection.** CLI → `bm25` (the caller may be a human at a terminal; opting into spend and egress should be explicit). MCP `refine_chain` → `agent` (its caller is an agent by definition, so ranking internally is strictly wasteful). This deliberately avoids sniffing for `CLAUDECODE` or similar — harness markers are fragile and change, and the entry point is knowable. A test pins each default, so a change that accidentally unified them fails rather than passes silently.
  - **`llm` and `auto` were NOT removed.** Headless and CI have no agent present; deleting the LLM path would remove ADEF's only unattended semantic capability. This inverts which mode is default, never which modes exist.
  - **The safe default belongs at the lowest layer, not at each entry point.** `RuleSimilarityAgent.run()`'s own default was still `auto`, and `refine_chain` forwards `**context` opaquely without ever naming `similarity_mode` — so "deterministic by default" held only because both entry points happened to pass it. ADEF advertises plugin entry points (`adef.commands`/`adef.agents`/`adef.mcp_tools`), so a third-party command calling `run_refine_chain(journal, det_id)` would have silently billed the user's key and egressed detection content, with no log line saying so.   - **Journal rendering must collapse whitespace; the returned payload must not.** Returning the verbatim query exposed a latent bug in the shared renderer: `_format_payload` joins a candidate's keys onto one line, which was only ever safe because `MemoryIndex._snippet` strips newlines. Real Sigma/SQL queries are multi-line, so on the new MCP default path the journal bullet severed, indented YAML became a markdown code block, and trailing fields orphaned. Fixed at the root with `_inline()` in `refine_chain.py`, applied at both interpolation sites — so any future step returning multi-line text is covered — while what the agent returns and the MCP caller receives stays verbatim. Sanitizing the payload instead would have defeated the feature.
  - **The MCP mode parameter is a `Literal`, not a `str`.** The MCP caller is an LLM, i.e. the caller most likely to invent a mode name; a plain `str` produced a tool schema saying only "string", and a hallucinated value surfaced as a traceback in the journal. `Literal` renders as a JSON-schema enum the model can read.
  - **Shipping the feature and shipping it *reachable* are different things.** `claude-plugin/skills/forge-stage/SKILL.md` never named `--similarity-mode`, and skills drive the CLI (MCP needs the `[mcp]` extra plus wiring). Caught by the second CodeRabbit round. The split it documents now is the same one the renderer enforces: the journal block is the ranked shortlist, `adef detection show <id>` is the full logic for both sides, and neither a title nor a preview is grounds for a duplicate verdict. Printing the shortlist to stdout in `agent` mode is the better product answer and belongs to the 10184 skill refresh, not here.
  - **Rule logic does not go in the journal at all.** Agent-mode results put neighbours' query text into the target's journal, and `MemoryIndex` indexes journal bodies — so the next similarity run saw D-0001's journal containing D-0002's query and scored the pair higher for no new evidence. The first fix capped the render at 300 chars, which bounded the amplification without removing it; the second CodeRabbit round pushed on it again and the cap turned out to be the wrong instrument. The query is the *neighbour's*, it already lives in that neighbour's catalog record keyed by an ID the journal does record, and a copy in a second place only goes stale. `_format_payload` now drops the `query` key at every nesting depth (`_JOURNAL_OMIT_KEYS`). The journal keeps the shortlist and the verdict; `adef detection show <id>` keeps the logic; the caller still receives `query` verbatim in the return payload. Deleting the field was smaller than the cap it replaced — and closes the feedback loop rather than narrowing it.
  - **The 300-char cap stays, for a different reason.** With `query` gone the corpus argument no longer needs it, but free-text fields that do belong in the journal — an LLM judge's `reasoning`, a snippet — still reach the renderer verbatim and can run long. The cap sits above `MemoryIndex`'s 240-char snippet so nothing previously rendered changes.
  - **Two CodeRabbit findings declined, on the record.** (1) *Filter journal-only detections out of the shortlist.* No: a journal-only detection — what `detection new` without `--source` and `hunt-promote` produce — is a real in-flight detection, and a draft near-duplicate is exactly what Refine should surface. Its enrichment collapses to empty values, which the caller reads the same way it reads a genuinely blank query: nothing to compare on logic. Filtering would trade a real recall loss for no behavioural gain. (2) *Render the query in a fenced block instead of collapsing it.* No: `_format_payload` renders candidates as one comma-joined line, so a fenced block means restructuring the whole renderer — and it would put more, not less, verbatim query text into the BM25 corpus. The journal is a log; the verbatim query reaches the caller through the return value.
  - **Explicitly deferred:** story 10188 (BM25 cannot surface cross-language or structurally-similar rules) is a *recall* problem no reranker can fix, and is untouched here — nothing in this branch changes which candidates reach the shortlist.
