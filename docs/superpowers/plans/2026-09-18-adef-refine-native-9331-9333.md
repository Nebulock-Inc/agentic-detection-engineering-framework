# ADEF Refine Chain — Native Similarity/Overlap/Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the three Refine-chain steps (Similarity, Overlap, Verification) native and vendor-free by default, replacing today's `ADEF_WRAPPER_*` env-var indirection to an unconfigured upstream agent, while preserving that env var as an opt-in override.

**Architecture:** Each step gets a real `adef/agents/*.py` implementation operating only on the local catalog (`Catalog.iter_records()`, `catalog/INDEX.yml`) and journals (`MemoryIndex`) — no network calls, no new vendor dependency. `RuleSimilarityWrapper` / `RuleOverlapWrapper` / `VerificationWrapper` become thin dispatchers: if `ADEF_WRAPPER_<KEY>` is set, behave exactly as today (delegate to the configured upstream class); if unset (the default, and the actual state of every real installation today), run the new native agent. `refine_chain.py` is untouched — the wrapper classes still expose the same `run(detection_id, **ctx) -> dict` shape `REFINE_STEPS` already calls.

**Tech Stack:** Python 3.10+, Click, PyYAML — no new runtime dependency. Reuses stdlib `hashlib`/`difflib`/`re` (the same primitives detect-vault's `RuleOverlapAgent._analyze_cluster_deterministic` already uses) and the existing `MemoryIndex` BM25 engine (`adef/core/memory.py`).

## Global Constraints

- **Similarity is dual-mode: BM25 by default, LLM-reranked when available, switchable via `--similarity-mode`.** (Revised 2026-09-18 per epic owner direction: ADEF is agentic by intent, so the deterministic path is the guaranteed fallback, not the ceiling.) No LLM SDK is a *required* dependency — `anthropic` becomes a new **optional** extra (`pip install '...[llm]'`), guarded by the same `try: import ... except ImportError` pattern `adef/mcp/server.py` already uses for the `mcp` extra. `tests/test_no_vendor_connectors.py` is unaffected either way — confirmed earlier that anti-goal is vendor *telemetry* connectors (CrowdStrike/Splunk/etc.), not LLM SDKs. See Task 2 for the retrieve-then-rerank design and the efficiency reasoning behind it.
- **`tests/test_no_new_engine_types.py` is CI-enforced and must stay green.** The closed engine set is exactly `{"sigma", "sql", "sch_sql", "composite"}` — four values, no `atomic_sql` (that's detect-vault's fifth engine, not ADEF's). Any new code referencing this set must reuse the constant added in Task 4, never re-type the literal list (a second literal list next to the existing ones could itself trip the regex scanner if it ever lists a 5th value by mistake).
- **`tests/test_no_vendor_connectors.py` is CI-enforced and must stay green.** No `import` of any forbidden vendor SDK. Not affected by this plan (no such imports are added), but every task's implementer must not introduce one.
- **`tests/test_schema_parity.py`'s invariant holds:** no code path in this plan writes under any `detections/` tree. Every agent in this plan is read-only against the catalog and read/append-only against journals via the existing `Journal` API.
- **Preserve the `ADEF_WRAPPER_*` escape hatch.** Do not delete `WrapperBase`/`_load_class()`. When an operator sets `ADEF_WRAPPER_RULE_SIMILARITY` (etc.), behavior must be byte-for-byte what it is today — the native path is only the *default* (unset-env-var) behavior.
- **Ruling (discovered during Task 2, applies identically to Tasks 3 and 5):** a journal-only detection (still at Find/Observe, no catalog record yet) makes every native agent raise `ValueError("No catalog record found for ...")`. Task 2's implementer found this breaks the pre-existing `tests/test_journal_lifecycle.py::test_full_forge_lifecycle_reads_coherently` invariant ("no raw Traceback in the journal") once a step goes native, because that case used to be silently masked by every step always being `WrapperUnavailable` (no wrapper was ever configured). Each of the three wrapper classes (`RuleSimilarityWrapper` done; `RuleOverlapWrapper`, `VerificationWrapper` below) must catch that specific `ValueError` from its native agent and re-raise it as `WrapperUnavailable` — the native agent's own `ValueError` stays as-is (each agent's own direct-call unit test depends on it), only the wrapper's dispatch translates it. The code blocks below already include this.
- **"Type validation" scope ruling (story 9333):** ADEF's field extractors (`_FIELD_EXTRACTORS` in `adef/commands/schema.py`) extract field *names* referenced by a query, not the literal values compared against them — there is no existing per-language value/type parser to check "is this comparison type-correct." Building that is a materially larger feature than this plan's scope. **This plan's "type validation" is: every field a rule references must resolve to a schema field that has a non-empty declared `type`** (schema completeness), not query-literal type-checking. Flag this scope reduction to the epic owner; it satisfies the letter of "field existence, types" without inventing an unverified type-inference layer.
- **Command decision for story 9333 (ruling):** extend `adef schema check` rather than add a new command. `schema check --detection D-XXXX` already exists and its docstring says it was "built for the authoring loop: validate the rule you just wrote" — exactly this use case. Task 4 extracts its logic into a callable core function so both the CLI and the new Verification agent can use it without duplicating the field-usage cross-reference.
- **Fixture-based cross-validation, not live detect-vault access.** All three stories ask to "validate against known duplicate/overlapping pairs in detect-vault." ADEF has no dependency on detect-vault at test time (and shouldn't gain one — ADEF must build and test standalone). Task 6 creates small YAML fixtures modeled on real detect-vault patterns (near-duplicate `sch_sql` predicates, a redundant pair, an out-of-taxonomy engine value) and asserts the native agents classify them correctly. This is the existing testing pattern in this repo (e.g. `tests/test_rule_discovery.py` uses fixtures, not a live external repo).

```python
# adef/core/corpus_text.py
"""The catalog-record text projection shared by search, similarity, and overlap.

Extracted from ``adef.commands.detection._record_search_text`` (2026-09-18) so
agents can build the same searchable text without importing a CLI module.
"""

from __future__ import annotations


def record_search_text(data: dict) -> str:
    """The catalog fields worth searching on — so a detection is findable by
    *what it detects* (title, MITRE, platform, source, query), not only by what
    its journal says."""
    parts = [
        str(data.get("title", "")),
        " ".join(data.get("mitre") or []),
        str(data.get("platform", "")),
        str(data.get("data_source", "")),
        str(data.get("format", "")),
        str(data.get("query", "")),
    ]
    return " ".join(p for p in parts if p)


__all__ = ["record_search_text"]
```

# Task 2: Native RuleSimilarityAgent — BM25 retrieval + optional LLM rerank (story 9331)

**Design rationale (why retrieve-then-rerank, not LLM-only or BM25-only):**

The story asks for "LLM semantic similarity." BM25 is lexical/keyword-based — it will
under-match true paraphrases (e.g. a title saying "credential dumping via LSASS" vs.
"extracting passwords from process memory" share almost no tokens despite being the same
technique). That's a real, honest limitation, and exactly the gap an LLM closes. But running
an LLM comparison against *every* rule in the catalog for every `refine` call scales cost and
latency linearly with corpus size — inefficient, and unnecessary. The standard, efficient IR
pattern is **retrieve-then-rerank**: a cheap deterministic pass (BM25) narrows the whole
catalog to a small shortlist (`top_k`, default 5), and the expensive step (the LLM judge)
only ever looks at that shortlist. This is also what detect-vault's own reference
`RuleSimilarityAgent` effectively does via its `batch_size` parameter — batching, not a full
corpus scan per call. BM25 remains the **required, always-available fallback**; the LLM path
is a **pure quality upgrade** layered on top when available, never a replacement for it.

**Mode selection — this is the piece the epic owner asked for explicitly:**

| `--similarity-mode` | Behavior |
|---|---|
| `bm25` | Always deterministic. Never imports or calls an LLM. |
| `llm` | Requires `ANTHROPIC_API_KEY` set and the `anthropic` package importable (the `llm` extra). If unavailable, raises `RuntimeError` with the install instruction — an explicit request for a capability that isn't there is an error, not a silent downgrade. If available but the API call itself fails at request time (network, rate limit, malformed response), falls back to the BM25 shortlist and reports `llm_error` in the result — an LLM outage must never break the Refine chain (matches `refine_chain.py`'s existing "chain must not abort" philosophy). |
| `auto` (default) | Uses `llm` if `ANTHROPIC_API_KEY` is set and `anthropic` is importable; otherwise transparently uses `bm25`. Same runtime-failure fallback as `llm` mode. |

```python
# adef/agents/rule_similarity.py
"""Rule-similarity search over the ADEF catalog — BM25 retrieval, optional
LLM rerank.

Answers "does a rule like this already exist?" in two stages:
1. Always: rank the whole catalog with the same BM25 index `adef detection
   search` ships (`adef.core.memory.MemoryIndex`) and take the top-K.
2. Optionally (`similarity_mode` "llm" or "auto" with an LLM available):
   ask an LLM judge to re-score just that shortlist for true semantic
   similarity (paraphrase/synonym matches BM25's lexical scoring misses).

The LLM step never scans the whole corpus — cost and latency stay bounded by
`top_k`, not catalog size. See the plan's Task 2 design rationale.
"""

from __future__ import annotations

import json
import os
from pathlib import Path
from typing import Any

from adef.core.catalog import Catalog
from adef.core.corpus_text import record_search_text
from adef.core.journal import Journal, workspace_journals_dir
from adef.core.memory import MemoryIndex

DEFAULT_LLM_MODEL = "claude-haiku-4-5-20251001"

_JUDGE_PROMPT = """You are a detection engineering expert. Given a target detection rule and a \
shortlist of candidates retrieved by keyword search, judge which candidates are a true semantic \
match to the target — the same underlying behavior, even if worded or implemented differently.

Target:
Title: {target_title}
MITRE: {target_mitre}
Query: {target_query}

Candidates:
{candidates_block}

Return ONLY a JSON array, one entry per candidate, in the same order given:
[{{"detection_id": "...", "confidence": 0.0-1.0, "reasoning": "one sentence"}}]"""


def _anthropic_importable() -> bool:
    try:
        import anthropic  # noqa: F401
    except ImportError:
        return False
    return True


def _llm_available() -> bool:
    if not os.environ.get("ANTHROPIC_API_KEY", "").strip():
        return False
    return _anthropic_importable()


class RuleSimilarityAgent:
    """Native replacement for the upstream RuleSimilarity wrapper agent."""

    def run(
        self,
        detection_id: str,
        workspace: Path | None = None,
        top_k: int = 5,
        similarity_mode: str = "auto",
        llm_client: Any | None = None,
        **ctx: Any,
    ) -> dict[str, Any]:
        journals_dir = workspace_journals_dir(workspace, create=False)
        ws = journals_dir.parent
        catalog = Catalog(ws)

        records: dict[str, dict] = {}
        record_text: dict[str, str] = {}
        for det_id, _path, data in catalog.iter_records():
            records[det_id] = data
            record_text[det_id] = record_search_text(data)
        target_text = record_text.get(detection_id)
        if target_text is None:
            raise ValueError(f"No catalog record found for {detection_id}")

        index = MemoryIndex(journals_dir=journals_dir)
        index.build(
            entries=list(Journal(journals_dir).iter_entries()),
            extra_text_for=lambda e: record_text.get(e.detection_id, ""),
        )
        hits = [
            h for h in index.search(target_text, limit=top_k + 1)
            if h.detection_id != detection_id
        ][:top_k]
        candidates = [
            {"detection_id": h.detection_id, "title": h.title, "score": h.score,
             "snippet": h.snippet, "reasoning": ""}
            for h in hits
        ]

        resolved_mode = similarity_mode
        if resolved_mode == "auto":
            resolved_mode = "llm" if (llm_client is not None or _llm_available()) else "bm25"

        if resolved_mode == "llm":
            if llm_client is None and not _llm_available():
                raise RuntimeError(
                    "similarity_mode='llm' requires ANTHROPIC_API_KEY and the 'llm' extra: "
                    "pip install 'agentic-detection-engineering-framework[llm]'"
                )
            if hits:
                try:
                    candidates = self._rerank_with_llm(records[detection_id], hits, llm_client)
                except Exception as exc:  # noqa: BLE001 — an LLM outage must not break refine
                    return {
                        "detection_id": detection_id,
                        "mode_used": "bm25_fallback",
                        "candidates": [
                            {"detection_id": h.detection_id, "title": h.title, "score": h.score,
                             "snippet": h.snippet, "reasoning": ""}
                            for h in hits
                        ],
                        "llm_error": str(exc),
                    }
```

```python
# adef/agents/rule_overlap.py
"""Native, vendor-free duplicate/complementary/redundant classification.

Deterministic port of detect-vault's `RuleOverlapAgent._analyze_cluster_deterministic`
(hashlib/difflib, stdlib only) — no LLM call. Operates within one MITRE
technique cluster at a time, using `catalog/INDEX.yml`'s `by_technique` map
(built by `Catalog.rebuild_index()`) rather than re-deriving grouping.
"""

from __future__ import annotations

import re
from dataclasses import dataclass
from difflib import SequenceMatcher
from pathlib import Path
from typing import Any

import yaml

from adef.core.catalog import Catalog
from adef.core.journal import workspace_journals_dir

_DUPLICATE_NEAR_THRESHOLD = 0.85  # matches detect-vault's RuleOverlapAgent reference


@dataclass
class Overlap:
    other_id: str
    overlap_type: str  # duplicate | complementary | redundant
    confidence: float
    reasoning: str


def _normalize_query(query_text: str) -> str:
    if not query_text:
        return ""
    normalized = query_text.lower()
    normalized = re.sub(r"\s+", " ", normalized)
    normalized = re.sub(r"\s*([=<>!(),])\s*", r"\1", normalized)
    return normalized.strip()


def _similarity(query_a: str, query_b: str) -> float:
    if not query_a or not query_b:
        return 0.0
    return SequenceMatcher(None, _normalize_query(query_a), _normalize_query(query_b)).ratio()


def classify_pair(record_a: dict, record_b: dict, id_a: str, id_b: str) -> Overlap:
    """Classify the relationship of ``record_b`` relative to ``record_a``.

    ``other_id`` on the returned ``Overlap`` is always ``id_b`` — callers
    build one ``Overlap`` per (target, cluster-mate) pair.
    """
    query_a, query_b = record_a.get("query", ""), record_b.get("query", "")
    norm_a, norm_b = _normalize_query(query_a), _normalize_query(query_b)

    if norm_a and norm_a == norm_b:
        return Overlap(id_b, "duplicate", 1.0, "Identical query logic after normalization")

    # Redundant (substring) must be checked BEFORE the near-duplicate ratio
    # threshold below — a "narrower by one extra AND clause" pair can score
    # >= 0.85 on SequenceMatcher (found live during Task 3: 0.852 on the test
    # fixture), which would otherwise misclassify a real redundant pair as a
    # duplicate. Exact-match duplicate above is unaffected (checked first,
    # unconditionally, on both branches).
    same_source = bool(record_a.get("data_source")) and record_a.get("data_source") == record_b.get("data_source")
    if same_source and norm_a and norm_b and norm_a != norm_b:
        # Strip one layer of outer wrapping parens before the substring check —
        # detect-vault's WHERE-only predicate convention wraps the whole
        # condition in `(...)`, which otherwise defeats substring matching
        # (found live during Task 6, against detect-vault-shaped fixtures).
        # ponytail: lstrip/rstrip strip a *character set*, not one matched
        # pair — correct for the single-outer-paren case real detect-vault
        # queries use, but would corrupt a query with nested parens
        # immediately at its outer edge (e.g. `((a) and (b))`). Upgrade to a
        # real matched-pair strip if a fixture ever needs that shape.
        norm_a_stripped = norm_a.lstrip("(").rstrip(")")
        norm_b_stripped = norm_b.lstrip("(").rstrip(")")
        if norm_a_stripped in norm_b_stripped:
            return Overlap(
                id_b, "redundant", len(norm_a_stripped) / len(norm_b_stripped),
                f"{id_b}'s query is a strict superset of {id_a}'s predicate — "
                f"{id_b} fires on a subset of what {id_a} already covers",
            )
        if norm_b_stripped in norm_a_stripped:
            return Overlap(
                id_b, "redundant", len(norm_b_stripped) / len(norm_a_stripped),
                f"{id_a}'s query is a strict superset of {id_b}'s predicate — "
                f"{id_a} fires on a subset of what {id_b} already covers",
            )

    ratio = _similarity(query_a, query_b)
    if ratio >= _DUPLICATE_NEAR_THRESHOLD:
        return Overlap(id_b, "duplicate", ratio, f"Near-identical query logic ({ratio:.0%} similar)")

    return Overlap(
        id_b, "complementary", ratio,
        "Same technique, distinct detection logic — different coverage angle",
    )


class RuleOverlapAgent:
    """Native replacement for the upstream RuleOverlap wrapper agent."""

    def run(self, detection_id: str, workspace: Path | None = None, **ctx: Any) -> dict[str, Any]:
        journals_dir = workspace_journals_dir(workspace, create=False)
        ws = journals_dir.parent
        catalog = Catalog(ws)

        target = None
        records: dict[str, dict] = {}
        for det_id, _path, data in catalog.iter_records():
            records[det_id] = data
            if det_id == detection_id:
                target = data
        if target is None:
            raise ValueError(f"No catalog record found for {detection_id}")

        index_path = ws / "catalog" / "INDEX.yml"
        by_technique: dict[str, list[str]] = {}
        if index_path.exists():
            index = yaml.safe_load(index_path.read_text(encoding="utf-8")) or {}
            by_technique = index.get("by_technique", {})

        cluster_ids: set[str] = set()
        techniques = list(target.get("mitre") or [])
        for technique in techniques:
            cluster_ids.update(by_technique.get(technique, []))
        cluster_ids.discard(detection_id)

        overlaps = [
            classify_pair(target, records[other_id], detection_id, other_id)
            for other_id in sorted(cluster_ids)
            if other_id in records
        ]

        return {
            "detection_id": detection_id,
            "techniques": techniques,
            "overlaps": [
                {
                    "other_id": o.other_id,
                    "overlap_type": o.overlap_type,
                    "confidence": round(o.confidence, 4),
                    "reasoning": o.reasoning,
                }
                for o in overlaps
            ],
        }


__all__ = ["RuleOverlapAgent", "Overlap", "classify_pair"]
```

```python
# adef/agents/verification.py
"""Native, vendor-free rule verification — would this rule pass schema
validation and the four-engine constraint?

Delegates to `adef.commands.schema.run_schema_check`, scoped to exactly one
detection, so the Refine chain's Verification step and the standalone
`adef schema check --detection` CLI share one implementation.
"""

from __future__ import annotations

from pathlib import Path
from typing import Any

from adef.commands.schema import run_schema_check
from adef.core.journal import workspace_journals_dir


class VerificationAgent:
    """Native replacement for the upstream Verification wrapper agent."""

    def run(self, detection_id: str, workspace: Path | None = None, **ctx: Any) -> dict[str, Any]:
        journals_dir = workspace_journals_dir(workspace, create=False)
        ws = journals_dir.parent

        result = run_schema_check(ws, detection_ids=(detection_id,))
        # rules_checked_ids already carries every catalog record the single-detection
        # scope matched, populated before unparseable/unmatched/engine-invalid
        # classification (Task 4) — the same "known to the catalog" signal
        # schema.py's own `check` CLI command uses for its not-found check.
        # Simpler than reconstructing it from three other result fields.
        if detection_id not in result.rules_checked_ids:
            raise ValueError(f"No catalog record found for {detection_id}")

        engine_error = result.engine_errors.get(detection_id)
        missing_fields = sorted(
            {
                field_name
                for fields in result.missing_from_schema.values()
                for field_name, ids in fields.items()
                if detection_id in ids
            }
        )
        undeclared_type_fields = result.undeclared_type_fields.get(detection_id, [])

        return {
            "detection_id": detection_id,
            "passed": not engine_error and not missing_fields,
            "engine_error": engine_error,
            "missing_schema_fields": missing_fields,
            "undeclared_type_fields": undeclared_type_fields,
        }


__all__ = ["VerificationAgent"]
```

```python
"""Verification step of the Refine chain — native by default.

Runs `VerificationAgent` (schema + four-engine constraint, vendor-free)
unless `ADEF_WRAPPER_VERIFICATION` is explicitly set, in which case behavior
is unchanged from before: delegate to the configured upstream class.
"""

from __future__ import annotations

import os
from typing import Any

from adef.agents.wrappers._base import WrapperBase, WrapperUnavailable


class VerificationWrapper(WrapperBase):
    binding_key = "VERIFICATION"

    def run(self, detection_id: str, **ctx: Any) -> dict[str, Any]:
        if os.environ.get(self._env_var(), "").strip():
            return super().run(detection_id=detection_id, **ctx)
        from adef.agents.verification import VerificationAgent

        try:
            result = VerificationAgent().run(detection_id=detection_id, **ctx)
        except ValueError as exc:
            # No catalog record for this detection yet (e.g. still journal-only
            # at Find/Observe — nothing to verify). Same treatment as
            # RuleSimilarityWrapper (Task 2): report it the same clean way as
            # an unconfigured wrapper instead of a raw traceback in the journal.
            raise WrapperUnavailable(str(exc)) from exc
        return {"detection_id": detection_id, "result": result}


__all__ = ["VerificationWrapper"]
```
