## ⚠️ Known adoption risks (input, 2026-07-17)

External design feedback surfaced adoption risks worth weighing before the next
build phase. **Full context lives in `docs/HANDOFF.md` → "Strategic feedback &
direction"**; the headline risks:

1. **Cold-start value inversion.** `adef catalog` over a large repo yields blank
   skeleton journals + an index — not a wow moment. The compelling zero-input
   deliverables (coverage summary, MITRE Navigator layer, duplicate report, gap
   view) aren't built yet. `adef catalog` should *end with a report*.
2. **Staleness kills trust.** The catalog is a snapshot; repos change weekly. No
   staleness detection exists yet (`adef sync` deferred). A confident AI answer
   from a stale catalog is the trust-killer — store a source-file hash / git SHA
   and make reads staleness-aware.
3. **Journal placement fights the PR workflow.** Journals in `~/work/adef-workspace/`
   don't travel with the rule or appear in review; a journals-in-repo mode would
   make the habit stick for git-based teams.
4. **Schema-from-queries blind spot.** Inferring schema only from used fields is
   the wrong dataset for finding gaps; layering known mappings (ECS/OCSF/CIM)
   would show what *could* exist.
5. **Evolve has no data seam.** Tuning/deprecation without FP rates/volumes is
   speculation; a `--results` import seam (like schema sampling) would fix it.
6. **Browse commands (`adef detection list/show`) are table stakes** and still
   deferred (story 7393).

These are **captured input, not decisions** — see HANDOFF for the sync/identity
strategy and the two target usage scenarios (git-repo vs. SIEM-export).

## ✅ Already Implemented in v0.1.0

### 1. CLI Commands (Fully Functional)

#### `adef init`
**File:** `adef/commands/init.py`

Creates workspace structure:
```
~/work/adef-workspace/
  ├── journals/
  ├── config/.adefconfig.yaml
  ├── AGENTS.md
  └── templates/DETECTION_FORGE.md
```

**Options:**
- `--path PATH` — custom workspace location

---

#### `adef detection` (FORGE Lifecycle)
**File:** `adef/commands/detection.py`

**Subcommands:**
- `adef detection new TITLE` — Create detection journal at Find stage
  - Options: `--owner`, `--rule-uuid`, `--workspace`
- `adef detection observe D-XXXX` — Advance to Observe stage
- `adef detection refine D-XXXX` — Advance to Refine stage + run orchestration chain
- `adef detection govern D-XXXX` — Advance to Govern stage
- `adef detection evolve D-XXXX` — Advance to Evolve stage

**All stage commands support:**
- `--note "text"` — Append free-text note to stage transition
- `--workspace PATH` — Custom workspace location

**Special behavior:**
- `refine` stage automatically invokes orchestration chain:
  - RuleSimilarity → RuleOverlap → Verification (if upstream agents available)
  - Results appended to journal

---

#### `adef hunt-promote H-XXXX`
**File:** `adef/commands/hunt_promote.py`

Promotes ATHF hunt to ADEF detection:
1. Loads hunt artifact from `ADEF_HUNT_ROOT`
2. Calls hunt promotion agent (configurable via env var)
3. Writes draft Sigma YAML to staging directory
4. Creates ADEF journal at Find stage with intel sources populated

**Options:**
- `--workspace PATH`
- `--rule-staging-root PATH` — Where to write draft YAML
- `--hunt-root PATH` — Where hunt artifacts live

**Environment variables:**
- `ADEF_HUNT_ROOT` — Hunt artifacts directory
- `ADEF_RULE_STAGING_ROOT` — Staging directory for drafted rules
- `ADEF_HUNT_RULE_GENERATOR` — Dotted path to generator class

---

#### `adef backfill journals`
**File:** `adef/commands/backfill.py`

Creates skeleton journals for existing upstream rules:
- Scans `ADEF_RULE_ROOT` for YAML files
- Creates `D-XXXX.md` journals for rules without journals
- Populates frontmatter from rule metadata

**Options:**
- `--workspace PATH`
- `--rule-root PATH` — External rule directory to scan
- `--limit N` — Backfill at most N rules
- `--dry-run` — Print plan without writing

### 2. MCP Server (`adef-mcp`)

**File:** `adef/mcp/server.py`

FastMCP server exposing tools for Claude Code, Cursor, Copilot.

**Tool Categories:**

#### Lifecycle Tools (`adef/mcp/tools/lifecycle_tools.py`)
- `forge_create(title, owner, rule_uuid, workspace)` → Create detection journal
- `forge_advance(detection_id, stage, note, workspace)` → Advance stage
- `forge_status(detection_id, workspace)` → Read frontmatter + current stage

#### Memory Tools (`adef/mcp/tools/memory_tools.py`)
- `memory_search(query, workspace)` → BM25 search over journals + upstream YAML

#### Agent Tools (`adef/mcp/tools/agent_tools.py`)
- `refine_chain(detection_id, workspace)` → Run Similarity → Overlap → Verification
- `hypothesis_from_intel(intel_url_or_text)` → Draft Find/Observe from CTI
- `tune_recommend(detection_id, signal_history)` → Tuning suggestions
- `deprecation_recommend(detection_id, signal_history)` → Keep/tune/deprecate verdict

#### Init Tools (`adef/mcp/tools/init_tools.py`)
- `workspace_init(workspace, force)` → Same as `adef init`
- `workspace_status(workspace)` → Check workspace structure

**Plugin Discovery:**
- Loads tools from `adef.mcp_tools` entry-point group
- Built-in tools registered same way as third-party (defensive loading)

### 3. Core Infrastructure

#### Journal Management (`adef/core/journal.py`)
**Key Classes:**
- `Journal` — CRUD operations on `journals/D-XXXX.md`
- `JournalEntry` — Parsed journal (frontmatter + content)

**Key Functions:**
- `Journal.create(detection_id, title, owner, rule_uuid)` → Write new journal from template
- `Journal.advance_stage(detection_id, stage, note)` → Atomic stage transition
- `Journal.read(detection_id)` → Parse existing journal
- `next_detection_id(journals_dir)` → Generate next D-XXXX ID

**Features:**
- Atomic writes (temp file + rename)
- Idempotent stage transitions
- Timestamped `## [ISO-8601] Stage: <stage>` blocks
- **Hard invariant:** Never writes to paths under `detections/` directories

**Frontmatter Fields:**
```yaml
id: D-XXXX
status: active
current_stage: find|observe|refine|govern|evolve
owner: email@example.com
created: ISO-8601
updated: ISO-8601
rule_uuid: optional-upstream-uuid
```

---

#### Memory Search (`adef/core/memory.py`)
- BM25 search over journal content + upstream rule YAML
- Indexes both journals and external rule files
- Returns ranked results for queries like "mshta.exe public directory"

---

#### Rule Bridge (`adef/core/rule_bridge.py`)
**Read-only** interface to upstream rule repositories:
- `iter_rules(rule_root)` → Scan YAML files
- Extract metadata (title, MITRE techniques, severity, etc.)
- **Never modifies upstream YAML** (enforced by design)

---

### 4. Agents

#### ADEF-Native Agents (`adef/agents/`)
- `hypothesis_from_intel.py` — Draft Find/Observe from CTI URL
- `tune_recommender.py` — Tuning suggestions based on signal history
- `deprecation_recommender.py` — Keep/tune/deprecate recommendations
- `hunt_promotion.py` — Hunt → detection conversion logic

#### Upstream Agent Wrappers (`adef/agents/wrappers/`)
Thin wrappers around 12 upstream rule-engineering agents:
- `rule_similarity.py` — Does similar rule exist?
- `rule_overlap.py` — Do triggers overlap with other rules?
- `verification.py` — Schema validation + four-engine constraint
- `coverage_analysis.py`, `detection_decision.py`, `detection_review.py`, etc.

**Pattern:**
- Lazy import via `ADEF_WRAPPER_<NAME>` env vars (dotted paths)
- Raises `WrapperUnavailable` if import fails
- Orchestration logs errors and continues (graceful degradation)

---

### 5. Orchestration

#### Refine Chain (`adef/orchestration/refine_chain.py`)
Runs when `adef detection refine` is invoked:
1. **RuleSimilarity** → Check for duplicate/similar rules
2. **RuleOverlap** → Check if triggers overlap with existing rules
3. **Verification** → Schema validation + four-engine check

Results appended to journal under `### Refine / <step>` headings.

Chain continues even if one step fails (partial results valuable).

### 6. Data & Templates

#### Detection Journal Template (`adef/data/templates/DETECTION_FORGE.md`)
Markdown template with:
- YAML frontmatter (id, status, owner, etc.)
- Five stage headings (`## Find`, `## Observe`, etc.)
- Used by `Journal.create()`

#### Stage Prompts (`adef/data/prompts/`)
Markdown prompts for each FORGE stage:
- `find.md` — What triggered this detection?
- `observe.md` — Characterize telemetry
- `refine.md` — Iterate rule with feedback
- `govern.md` — Deployment gates
- `evolve.md` — Tuning/deprecation

Rendered into journal blocks during stage transitions.
