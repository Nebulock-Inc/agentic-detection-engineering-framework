# ADEF Data Schema Storage Design

**Date:** 2026-07-14  
**Status:** Approved for Implementation  
**Version:** 1.0

---

## Overview

ADEF's schema storage capability gives detection engineers a living inventory of their data model — what fields exist in their rules vs. their actual data, with types, population rates, and descriptions. This enables schema-grounded detection authoring and drift detection (when logging changes break rules).

**Core value:** Rules expect `command_line` at 100% population, but data sample shows only 40% → detection is likely broken.

---

## Goals

### Primary
1. **Inventory existing rule fields** — parse SQL/SPL/CQL/KQL rules, extract field names
2. **Discover actual data shape** — infer types, populations, sample values from piped query results
3. **Merge both sources** — single schema file per data source showing rule expectations vs. data reality
4. **Enable drift detection** — re-sample data weeks later, detect population drops or missing fields
5. **Provider-agnostic LLM integration** — generate field descriptions using Claude, OpenAI, or custom providers

### Non-Goals (v1)
- Sigma rule parsing (explicitly out of scope)
- Full AST parsing for query languages (simple regex extraction is sufficient)
- Automatic query execution (results-in seam: user runs queries, ADEF consumes results)
- Normalization or translation between vendor schemas (schema is literal field inventory)

---

## Architecture

### Schema File Structure

**Location:** `<workspace>/schema/<source>.yml`

**Format:**
```yaml
source: edr_process
query_language: sql  # or spl, cql, kql
last_rule_scan: 2026-07-14T10:00:00-04:00
last_data_sample: 2026-07-14T10:15:00-04:00
sample_window: 30d
sample_size: 10000

fields:
  - name: parent_image
    in_rules: true      # found during rule parsing
    in_data: true       # found during data sampling
    type: string
    population: 0.98    # 98% of sampled rows have this field
    sample_values: ["C:\\Windows\\System32\\cmd.exe", "mshta.exe", null]
    description: "Executable path of the parent process"
    description_source: generated  # or manual
    
  - name: command_line
    in_rules: true
    in_data: true
    type: string
    population: 0.85
    sample_values: ["powershell.exe -enc ...", null]
    description: "Full command line arguments passed to the process"
    description_source: generated
    
  - name: process_id
    in_rules: false     # exists in data but no rules reference it yet
    in_data: true
    type: integer
    population: 1.0
    sample_values: [1234, 5678, 9012]
    description: "Unique identifier for the process instance"
    description_source: generated
    
  - name: parent_pid
    in_rules: true      # rule expects this but it's missing from data sample
    in_data: false
    type: null
    population: 0.0
    sample_values: []
    description: "Process ID of the parent process"
    description_source: generated
```

**Key fields:**
- `in_rules` — field found during rule parsing (Option 1)
- `in_data` — field found during data sampling (Option 2)
- `type` — inferred from first non-null value in sample (`null` if never seen)
- `population` — fraction of sampled rows where field is non-null (0.0 to 1.0)
- `sample_values` — up to 3 example values from the data sample (includes `null` if present)
- `description` — generated by LLM or manually edited by user
- `description_source` — `generated` (LLM) or `manual` (user edited), prevents overwrites on rescan

**Timestamps** track when each source was last refreshed (rules vs data), so you know if schema is stale.

## CLI Commands

### `adef schema init <source>`

**Purpose:** Interactive wizard to build initial schema file.

**Flow:**
1. Prompt: "Which query language does `<source>` use? [SQL/SPL/CQL/KQL]"
2. Prompt: "Do you have existing rules to scan? [Y/n]"
   - If yes: "Path to rules directory: [default: $ADEF_RULE_ROOT or config]"
   - Runs rule parser → extracts field names → marks `in_rules: true`
3. Prompt: "Sample data now to discover field types/populations? [Y/n]"
   - If yes: Generates discovery query for their language, displays it
   - "Run this query and pipe results: `<their-query-tool> | adef schema init <source> --stdin`"
   - Or: "Pipe results now (press Enter, paste JSON/CSV, Ctrl+D):"
   - Reads stdin → infers types/populations → marks `in_data: true`
4. Batch LLM call: generates descriptions for all fields (marked `description_source: generated`)
5. Writes `<workspace>/schema/<source>.yml`
6. Appends entry to `<workspace>/schema/PROGRESS.md` (if first schema in workspace)

**Flags:**
- `--rule-root <path>` — override config for rules directory (headless mode)
- `--stdin` — read data sample from stdin (skip interactive paste)
- `--skip-rules` — only do data sampling
- `--skip-data` — only do rule parsing

**Output:**
```
Schema initialized: schema/edr_process.yml
  Fields from rules: 12
  Fields from data: 15
  Overlap: 10
  Rules-only (missing in data): 2 ⚠️
  Data-only (not used in rules): 3
  
Next steps:
  - Review: adef schema show edr_process
  - Edit descriptions: schema/edr_process.yml
  - Update data later: adef schema update edr_process --results -
```

---

### `adef schema update <source> --results -`

**Purpose:** Re-sample data to refresh types/populations (e.g., detect drift).

**Flow:**
1. Reads existing `schema/<source>.yml`
2. Reads piped data sample (JSON/CSV from stdin)
3. For each field in data:
   - If field exists in schema: update `population`, `type`, `sample_values`, `last_data_sample` timestamp
   - If new field: append to schema with `in_rules: false, in_data: true`, generate description via LLM
4. Marks fields that disappeared: if field had `in_data: true` but isn't in new sample, set `population: 0.0`, add warning in output
5. Writes updated schema

**Output:**
```
Schema updated: schema/edr_process.yml
  
Drift detected:
  - command_line: population 0.98 → 0.85 (dropped 13%)
  - parent_pid: was in data, now missing (population 0.65 → 0.0) ⚠️
  
New fields discovered:
  - process_hash (sha256, population 0.92)
```

---

### `adef schema rescan <source>`

**Purpose:** Re-parse rules to refresh `in_rules` flags (e.g., after adding new detections).

**Flow:**
1. Reads existing `schema/<source>.yml`
2. Parses rules again from `--rule-root`
3. Updates `in_rules` flags for all fields
4. New fields found in rules: append with `in_rules: true, in_data: false`, generate description via LLM (marked `generated`)
5. Existing fields with `description_source: manual` are NOT regenerated
6. Writes updated schema

**Output:**
```
Schema rescanned: schema/edr_process.yml
  
New fields in rules:
  - process_integrity_level (used in 2 new detections)
  
Fields no longer in rules:
  - legacy_field_name (removed from all detections)
```

---

### `adef schema show <source>`

**Purpose:** Display schema (read-only).

**Output:**

## Rule Parsing (Option 1)

**Goal:** Extract field names from SQL/SPL/CQL/KQL rules with 99%+ accuracy.

**Approach:** Full AST parsing for SQL (foundational data source), enhanced regex for others.

### SQL
**Library:** `sqlglot` — production-grade SQL parser supporting multiple dialects

```python
import sqlglot
from sqlglot.expressions import Column

def extract_sql_fields(query: str, dialect: str = "postgres") -> set[str]:
    """Extract all column references from SQL query using AST."""
    try:
        parsed = sqlglot.parse_one(query, dialect=dialect)
        fields = set()
        
        # Walk AST and collect all Column nodes
        for node in parsed.walk():
            if isinstance(node, Column):
                # Get fully qualified name (table.column or just column)
                field_name = node.name
                if node.table:
                    field_name = f"{node.table}.{field_name}"
                fields.add(field_name)
        
        return fields
    except Exception as e:
        # Fallback to empty set, log error
        return set()
```

**Supported dialects:** postgres, mysql, clickhouse, bigquery, snowflake, etc.

**Coverage:** 99%+ — handles subqueries, CTEs, window functions, complex joins, aliases.

### Splunk SPL
**Approach:** Enhanced regex (no official parser available)

```python
# Patterns for SPL field extraction:
# - field=value, field!=value, field<value, field>value
# - where field > 100
# - stats count by field1, field2
# - table field1, field2, field3
# - eval new_field = field1 + field2
# - rename old_field as new_field
# - fields + field1, - field2

FIELD_COMPARISON_RE = re.compile(r'\b([a-z_][a-z0-9_.]*)\s*[=<>!]+', re.IGNORECASE)
STATS_BY_RE = re.compile(r'\bby\s+([a-z_][a-z0-9_., ]+)', re.IGNORECASE)
TABLE_RE = re.compile(r'\btable\s+([a-z_][a-z0-9_., ]+)', re.IGNORECASE)
EVAL_RE = re.compile(r'\beval\s+\w+\s*=\s*([a-z_][a-z0-9_.]*)', re.IGNORECASE)
FIELDS_RE = re.compile(r'\bfields\s+[+-]?\s*([a-z_][a-z0-9_., ]+)', re.IGNORECASE)
RENAME_RE = re.compile(r'\brename\s+([a-z_][a-z0-9_.]*)', re.IGNORECASE)

def extract_spl_fields(query: str) -> set[str]:
    """Extract field names from SPL query using enhanced regex."""
    fields = set()
    
    # Apply all patterns
    for pattern in [FIELD_COMPARISON_RE, STATS_BY_RE, TABLE_RE, 
                    EVAL_RE, FIELDS_RE, RENAME_RE]:
        matches = pattern.findall(query)
        for match in matches:
            # Split comma-separated fields
            for field in match.split(','):
                field = field.strip()
                if field:
                    fields.add(field)
    
    return fields
```

**Coverage:** ~95% — misses dynamic field names and complex macros.

### CrowdStrike CQL
**Approach:** Enhanced regex (CQL syntax is simpler than SPL)

```python
# CQL patterns:
# - #event_simpleName=ProcessRollup2
# - ComputerName="HOSTNAME"
# - FileName="cmd.exe"
# - CommandLine contains "powershell"

FIELD_EQUALS_RE = re.compile(r'\b([#A-Z][a-zA-Z0-9_]*)\s*[=!]', re.IGNORECASE)
FIELD_CONTAINS_RE = re.compile(r'\b([#A-Z][a-zA-Z0-9_]*)\s+(?:contains|like)', re.IGNORECASE)

def extract_cql_fields(query: str) -> set[str]:
    """Extract field names from CQL query."""
    fields = set()
    
    for pattern in [FIELD_EQUALS_RE, FIELD_CONTAINS_RE]:
        matches = pattern.findall(query)
        fields.update(matches)
    
    return fields
```

**Coverage:** ~95% — CQL syntax is more constrained than SPL.

### Defender KQL
**Approach:** Enhanced regex (KQL is pipe-based like SPL)

```python
# KQL patterns:
# - DeviceProcessEvents | where FileName == "cmd.exe"
# - | where ProcessCommandLine contains "powershell"
# - | project FileName, ProcessCommandLine, InitiatingProcessFileName
# - | summarize count() by ComputerName

FIELD_COMPARISON_RE = re.compile(r'\b([A-Z][a-zA-Z0-9_]*)\s*[=<>!]+', re.IGNORECASE)
PROJECT_RE = re.compile(r'\|\s*project\s+([A-Za-z0-9_., ]+)', re.IGNORECASE)
SUMMARIZE_BY_RE = re.compile(r'\|\s*summarize\s+.*\bby\s+([A-Za-z0-9_., ]+)', re.IGNORECASE)

def extract_kql_fields(query: str) -> set[str]:
    """Extract field names from KQL query."""
    fields = set()
    
    for pattern in [FIELD_COMPARISON_RE, PROJECT_RE, SUMMARIZE_BY_RE]:
        matches = pattern.findall(query)
        for match in matches:
            for field in match.split(','):
                field = field.strip()
                if field:
                    fields.add(field)
    
    return fields
```

**Coverage:** ~95% — misses dynamic column names and complex operators.

---

**File scanner:**
```python
def extract_fields_from_rules(rule_root: Path, language: str) -> set[str]:
    """Scan all rule files, extract field names based on language."""
    fields = set()
    extractors = {
        'sql': extract_sql_fields,
        'spl': extract_spl_fields,
        'cql': extract_cql_fields,
        'kql': extract_kql_fields,
    }
    extractor = extractors[language]
    
    for rule_file in rule_root.rglob("*.yml"):  # or *.sql, *.spl based on config
        content = rule_file.read_text()
        # Parse YAML to get query content, or read raw if it's a query file
        query = extract_query_from_file(content, language)
        fields.update(extractor(query))
    
    return fields
```

**Dependencies:**
- `sqlglot` — for SQL parsing (high-fidelity AST)
- No additional deps for SPL/CQL/KQL (enhanced regex)

**Future enhancement:** If better parsers become available for SPL/CQL/KQL, swap in the extractor function without changing the interface.

## Data Sampling (Option 2)

**Goal:** Infer field types, populations, sample values from piped query results.

### Input Format
Accepts JSON or CSV from stdin:

**JSON:** Array of objects
```json
[
  {"parent_image": "cmd.exe", "command_line": "whoami", "process_id": 1234},
  {"parent_image": null, "command_line": "ls -la", "process_id": 5678}
]
```

**CSV:** Header row + data rows
```csv
parent_image,command_line,process_id
cmd.exe,whoami,1234
,ls -la,5678
```

### Type Inference
```python
def infer_type(values: list) -> str:
    """Infer type from first non-null value."""
    for v in values:
        if v is None or v == "":
            continue
        if isinstance(v, bool):
            return "boolean"
        if isinstance(v, int):
            return "integer"
        if isinstance(v, float):
            return "float"
        if isinstance(v, str):
            # Simple heuristics:
            if re.match(r'^\d{4}-\d{2}-\d{2}', v):
                return "datetime"
            return "string"
    return "null"  # all values were null
```

### Population Calculation
```python
def calculate_population(values: list) -> float:
    """Fraction of non-null values."""
    if not values:
        return 0.0
    non_null = sum(1 for v in values if v is not None and v != "")
    return non_null / len(values)
```

### Sample Values
```python
def get_sample_values(values: list, max_samples: int = 3) -> list:
    """Return up to max_samples unique values, including null if present."""
    seen = set()
    samples = []
    has_null = False
    
    for v in values:
        if v is None or v == "":
            has_null = True
            continue
        if v not in seen:
            seen.add(v)
            samples.append(v)
            if len(samples) >= max_samples:
                break
    
    if has_null:
        samples.append(None)
    
    return samples[:max_samples]
```

**Ponytail note:** Stdlib type checking + simple heuristics. No pandas/numpy dependency.

When user opts to sample data during `adef schema init`, ADEF generates a query template:

**SQL:**
```sql
SELECT *
FROM <source>

LIMIT 10000;
```

**SPL:**
```spl
index=<source> earliest=-30d
| head 10000
```

**CQL:**
```
#event_simpleName=*
| limit 10000
```

**KQL:**
```kql
<source>
| where TimeGenerated > ago(30d)
| limit 10000
```

**LLM call (optional):** If user provides additional context during init ("I want to sample process events from our EDR"), LLM can customize the query (add filters, adjust time window). But default templates work without LLM.

### Fallback Strategy

If LLM call fails (no API key, rate limit, network error):
1. Log warning to stderr
2. Set descriptions to empty string with `description_source: failed`
3. Schema is still usable (descriptions are optional)
4. User can re-run `adef schema regenerate-descriptions <source>` later (or manually edit YAML)

## Agent Skill (`adef-schema`)

**Purpose:** Conversational wrapper that guides users through schema setup and maintenance, can orchestrate data discovery via user's MCP.

**Install:** `adef skills install` (or manually copy to `.claude/skills/adef-schema.md`)

### Skill Triggers
- User says: "set up my data schema", "initialize schema", "what fields do I have?"
- Explicit: `/adef-schema`

### Skill Workflow

**For initial setup:**
1. Ask: "What's your primary data source name?" (e.g., `edr_process`, `cloudtrail_events`)
2. Ask: "Which query language? [SQL/SPL/CQL/KQL]"
3. Ask: "Do you have existing detection rules I should scan?" 
   - If yes: get path, call `adef schema init <source> --rule-root <path> --skip-data`
4. Ask: "Want to sample your data now to discover field types?"
   - If yes: "I can generate a discovery query. Do you have an MCP tool to run it, or should I show you the query to run manually?"
     - **If MCP available:** Skill calls user's MCP tool (e.g., `@splunk`, `@clickhouse`), gets results, pipes to `adef schema init <source> --stdin`
     - **If manual:** Shows query, waits for user to paste results or pipe
5. Schema created, skill shows summary: "Found X fields from rules, Y from data, Z overlap. Review with `adef schema show <source>`"

**For updates (drift detection):**
1. User: "check if my schema has drifted"
2. Skill: "I'll generate a fresh sample query. Run and pipe results, or I can use your MCP?"
3. User provides data → skill calls `adef schema update <source> --results -`
4. Skill summarizes drift: "command_line population dropped 13%, parent_pid went missing"

**For rescan (after adding rules):**
1. User: "I added new detections, update the schema"
2. Skill calls `adef schema rescan <source>`
3. Skill summarizes: "Found 2 new fields in rules: process_integrity_level, process_hash"

## Testing Strategy

### Unit Tests
- **Rule parsers:** Known queries → expected field lists for each language (SQL/SPL/CQL/KQL)
- **Data sampler:** Known JSON/CSV → expected types, populations, sample values
- **LLM client:** Mock provider responses, test fallback on failure
- **Schema merge logic:** Fields from rules + fields from data → correct merged YAML structure

### Integration Tests
